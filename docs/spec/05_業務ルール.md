# 05 業務ルール・入力検証・変換ロジック

> 対象: 車両管理プラグイン v1.0.0。実装元: `includes/class-vehicle.php`, `includes/class-master.php`, `admin/assets/admin.js`

## 1. 入力検証ルール（保存時）

検証はサーバー側 `VM_Vehicle::validate()`。フォーム送信前にブラウザ側でも車台番号のみ検証する。

| # | ルール | エラーメッセージ |
|---|---|---|
| V1 | 運輸支局が空でない | 運輸支局は必須です。 |
| V2 | 分類番号が空でない | 分類番号は必須です。 |
| V3 | 用途区別が空でない | 用途区別は必須です。 |
| V4 | 一連指定番号が空でない | 一連指定番号は必須です。 |
| V5 | 車台番号が空でない | 車台番号は必須です。 |
| V6 | 車台番号は正規表現 `^[A-Za-z0-9\-_]+$` に一致 | 車台番号は半角英数字・ハイフン・アンダースコアのみ使用できます。 |
| V7 | 一連指定番号が既存と重複しない（DBのUNIQUE制約で検出） | 一連指定番号「○○」はすでに登録されています。 |

- 複数エラーは `<br>` 区切りでまとめて表示される。
- **値がマスタに存在するかは検証しない**（運輸支局・分類番号・用途区別はマスタ外の文字列でも保存できる。画面のプルダウンから選ぶ限り発生しない）。
- 数値の範囲・桁数、日付の正当性（実在日か）、有効期限と登録日の前後関係は検証しない。
- 編集時に一連指定番号を他の車両と同じ値に変えると V7 で拒否される。

### データ整形（サニタイズ）
| 対象 | 処理 |
|---|---|
| 文字列項目 | WordPress の `sanitize_text_field`（タグ除去・前後空白除去・改行除去） |
| 数値（整数）項目 | 空欄 → NULL、それ以外は `intval` |
| `passenger_capacity` | 空欄でも `intval`（空→0）。他の整数項目と異なり NULL にならない |
| `displacement` | 空欄 → NULL、それ以外は `floatval` |
| 日付 | 和暦/ISO文字列 → DATE（下記） |
| 既定値（POST に項目が無い場合） | 種別=普通、事業用の別=事業用、定員=2、燃料=軽油 |
| 保存時 | 項目が空の文字列でも DB には空文字で入る（NULLにはならない。CSV取込は空→NULL） |

## 2. 和暦・日付ルール

### 2.1 入力 → 保存（`wareki_to_date` / `wareki_to_ym`）
| 入力例 | 結果 |
|---|---|
| `2023-04-01`（日付）/ `2023-04`（年月） | そのまま保存 |
| `令和5年4月1日` | 2023-04-01（年 = 2018 + 令和年） |
| `平成30年12月31日` | 2018-12-31（年 = 1988 + 平成年） |
| `昭和63年1月1日` | 1988-01-01（年 = 1925 + 昭和年） |
| 年月のみの欄: `令和5年4月` | 2023-04 |
| 上記以外（例: `R5.4.1`, `令和元年5月1日`, 空欄） | **NULL（未入力扱い）で保存。エラーにならない** |

- 数字の間のスペースは許容（`令和 5 年 4 月 1 日` 可）。
- 「元年」表記は変換できない。「令和1年5月1日」と数字で入力する。
- 全角数字は変換できない（正規表現が半角数字 `\d` 前提）。
- 実在しない日付（例: 2月30日）の検証はしない。DATE列の挙動（MySQLの設定）に依存する。
- 元号と西暦年月日の整合（例: 平成40年）は検証しない。

### 2.2 保存 → 表示（`date_to_wareki` / `ym_to_wareki`）
| 範囲 | 表示 |
|---|---|
| 2019-05-01 以降 | 令和（年 = 西暦 − 2018） |
| 1989-01-08 〜 2019-04-30 | 平成（年 = 西暦 − 1988） |
| 1989-01-07 以前 | 昭和（年 = 西暦 − 1925） |
| NULL / `0000-00-00` | 空表示 |

- 年月のみ（`ym_to_wareki`）: 2019年5月以降=令和、1989年以降（〜2019年4月）=平成、それ以前=昭和。**1989年1月は平成扱い**（実際は1月1〜7日が昭和64年のため、日単位の関数と境界がわずかに異なる）。
- 年は「元年」ではなく **「1年」** と表示される（例: 令和1年5月1日）。

## 3. 有効期限の判定ルール

基準日は**サーバーの現在日付**（PHP `date('Y-m-d')`）。

| 状態 | 条件 | 一覧の表示 | 絞り込み値 |
|---|---|---|---|
| 期限切れ | `expiry_date` < 今日 | 薄赤の行 + 「期限切れ」バッジ | `expired`（期限切れのみ） |
| 期限間近 | 今日 ≤ `expiry_date` ≤ 今日+30日 | 薄黄の行 + 「30日以内」バッジ | `soon`（有効期限間近（30日以内）） |
| 有効 | `expiry_date` ≥ 今日 | 色なし（30日超） | `valid`（期限切れを除く） |
| 未設定 | `expiry_date` が NULL | 色なし | **すべての期限絞り込みで除外** |

- 満了日**当日**は「期限切れ」ではなく「30日以内」扱い。
- `valid`（期限切れを除く）には期限間近の車両も含まれる。
- 30日は固定値で設定画面からは変更できない（コード内の定数的な記述）。

## 4. 一覧の並べ替え・絞り込み・件数

- 並べ替え許可カラム: `serial_number`, `registration_date`, `expiry_date`, `transport_bureau`, `id`（それ以外は `serial_number`）。
- 初期表示: 一連指定番号の昇順（文字列順）。
- 1ページ 20 件。件数は絞り込み条件と同一条件で集計。
- 運輸支局の絞り込み: 完全一致。選択肢はDBに実在する運輸支局のみ（マスタではなく車両データ由来）。

## 5. マスタ管理ルール（`VM_Master`）

| 操作 | 条件・動作 | エラーメッセージ |
|---|---|---|
| 追加 | 前後空白除去・タグ除去後、空でない | 「○○を入力してください。」 |
| 追加 | 最大文字数以内（運輸支局50／分類番号10／用途区別10、`mb_strlen`） | 「○○は N 文字以内で入力してください。」 |
| 追加 | 既存と重複しない（厳密一致） | 「「○○」はすでに登録されています。」 |
| 追加 | 末尾に追加される | － |
| 削除 | その値を使う車両が0件 | 「「○○」は N 件の車両で使用されているため削除できません。」 |
| 並べ替え | 1つ上/下へ入れ替え（端は何もしない） | － |
| 名前の変更（リネーム） | **機能なし**（削除→追加で対応するが、使用中は削除できないため、車両側の付け替えは CSV 上書き等が必要） | － |

- 削除可否は車両テーブルの該当カラムを `GROUP BY` した件数で判定する。

## 6. タグ（入力補助）の自動生成ルール（`VM_Vehicle::rebuild_tags`）

実行タイミング: **CSV取込の本実行後のみ**（プレビュー時や、フォームからの個別登録・更新・削除では更新されない）。

| タグ対象 | ルール |
|---|---|
| 車名 `vehicle_name` / 型式 `model` / 原動機の型式 `engine_model` / リーフスプリング `leaf_spring` | 空でない値のうち、**3件以上の車両で使用**されている値。使用数の多い順 |
| 車台番号 `chassis_number` | 正規表現 `^([A-Z0-9]+)-` で取れる**ハイフンまでの接頭辞**（大文字英数字のみ。例: `FR1AH-`）のうち、3件以上で使われているもの（出現順） |

- 結果で `vm_tag_data` を**丸ごと置換**する。該当が1件も無い項目は空配列になり、有効化時の初期タグも消える。
- 小文字を含む接頭辞（例: `fr1ah-`）は対象外。
- 有効化時の初期タグは `04_データ設計.md` 参照。
- タグの表示・挙動は `03_画面仕様.md`。

## 7. 固定の選択肢（マスタ化されていない）

| 項目 | 選択肢 | 変更方法 |
|---|---|---|
| 用途 | 特種, 貨物 | ソース変更が必要（`vehicle-form.php`） |
| 車体の形状 | 冷蔵冷凍車, バン | 同上 |
| ブレーキ | ドラム, ディスク | 同上 |
| 燃料の種類 | 軽油, ガソリン, LPG, 電気, ハイブリッド | 同上 |

CSV取込ではこれらの選択肢外の文字列も、そのまま保存される。
