# 06 CSV一括登録 詳細仕様

> 対象: 車両管理プラグイン v1.0.0。実装元: `VM_Vehicle::ajax_csv_import()`（`includes/class-vehicle.php`）、画面 `admin/views/vehicle-csv.php`、制御 `admin/assets/admin.js`（`initCsvPage`）

## 1. 概要

車検証項目を並べた CSV を取り込み、車両を一括で新規登録（または上書き更新）する。1回目は「プレビュー」（DBへ書き込まない検証）、2回目が「本実行」。照合キーは**一連指定番号**。

- 権限: 画面表示は `access_custom_plugins`、処理は `edit_custom_plugins`、nonce は `vm_csv_nonce`
- 通信: AJAX `action=vm_csv_import`（multipart/form-data）。パラメータ: `csv_file`, `duplicate_mode`（`skip`|`overwrite`）, `preview`（`1`|`0`）, `nonce`

## 2. ファイル形式

| 項目 | 仕様 |
|---|---|
| 拡張子 | 画面の選択ダイアログは `.csv` に限定（サーバー側で拡張子は検査しない） |
| 文字コード | 自動判定。①先頭が UTF-8 BOM → BOM除去しUTF-8 ②UTF-8として不正 → Shift-JIS（CP932/SJIS-win）から変換 ③それ以外 → UTF-8 |
| 改行 | CRLF / CR / LF いずれも可 |
| 区切り | カンマ。囲み文字は `"`（PHP `str_getcsv`） |
| 1行目 | 見出し行（必須）。列名で項目を特定する（**列の順序は自由**、不要な列は省略可） |
| 空行 | 無視 |
| サイズ | コード上の上限なし（PHP/サーバー設定の `upload_max_filesize` 等に従う） |

**注意**: 行は先に改行で分割されてから CSV 解析されるため、**セル内に改行を含むデータは正しく読めない**。

### ⚠ 高さ列の見出し
ソースコード上、高さの見出しは **`高さ(cm）`**（開き括弧が半角 `(`、閉じ括弧が全角 `）`）と定義されている。他の列（`長さ（cm）` 等）は両方とも全角括弧。CSV の見出しが `高さ（cm）`（全角括弧）だと**一致せず、高さは取り込まれない（エラーも出ない）**。CSV 見出しを上記表記どおりに合わせるか、コードを修正する必要がある。

## 4. 処理フロー

1. 権限・nonce 確認 → ファイル受信確認（失敗: 「ファイルのアップロードに失敗しました。」）
2. 文字コード判定・変換、改行で行分割
3. 1行目を見出しとして列位置を特定
4. 各データ行について:
   1. 空行 → 無視
   2. 見出しに「車台番号」列が無い、または当該行の車台番号が空 → **スキップ件数に加算**（エラーにはならない）
   3. 34列分を `DBカラム` へ変換（空文字は NULL に変換。CSVに無い列も NULL になる）
   4. `serial_number` が空 → エラー「一連指定番号が空です。」→ 次の行へ
   5. 車台番号が `^[A-Za-z0-9\-_]+$` に合わない → エラー「車台番号に全角文字が含まれています: ○○」
   6. **プレビューの場合**: 先頭10件を返却用に保存、有効行カウント（`inserted` に加算）→ 次の行へ（DB書込なし・重複判定なし）
   7. **本実行の場合**: 一連指定番号で既存を検索
      - 既存あり・モード `overwrite` → UPDATE（成功: 更新件数+1、失敗: エラー「UPDATE 失敗: …」）
      - 既存あり・モード `skip` → スキップ件数+1
      - 既存なし → INSERT（成功: 新規件数+1、失敗: エラー「INSERT 失敗: …」）
5. 本実行の場合のみ、タグを再計算（`VM_Vehicle::rebuild_tags`、`05_業務ルール.md` 参照）
6. 結果を JSON で返却

## 5. レスポンス

```json
{
  "success": true,
  "data": {
    "inserted": 10,       // 新規登録件数（プレビュー時は「有効行数」）
    "updated": 2,         // 上書き更新件数
    "skipped": 3,         // スキップ件数（車台番号空行＋重複スキップ）
    "errors": [ {"row": 5, "msg": "一連指定番号が空です。"} ],  // row はCSVの行番号（ヘッダーが1行目）
    "preview_rows": [ {...}, ... ],  // プレビュー時のみ。先頭10件のDB形式データ
    "preview": false
  }
}
```

画面の表示: プレビューでは `inserted` を「有効行合計」として表示。エラー一覧は**本実行の結果画面でのみ表示**され、プレビューではエラー行は表示されない（返却はされるが画面は使わない）。

## 6. 結果件数の読み方

| 表示 | 意味 |
|---|---|
| 新規登録 | INSERT に成功した行数 |
| 上書き更新 | 既存を UPDATE した行数 |
| スキップ | 車台番号が空の行 ＋ 重複でスキップした行 |
| エラー | 一連指定番号が空／車台番号が全角混じり／DB書込失敗の行（理由と行番号付き） |

## 7. 仕様上の重要な注意点（取り込み前に必ず確認）

1. **日付は「令和○年○月○日」「平成」「昭和」形式か `YYYY-MM-DD` のみ対応**。Excel で日付セルを `2023/4/1` のように保存した CSV は変換できず、**日付は黙って空（NULL）になる**。取込前に書式を確認する。
2. **上書きモードの影響範囲**: 1行ごとに 34 列すべてを更新対象とするため、**CSVに存在しない列・空欄の列は、既存の値が NULL で上書き（消去）される**。既定値（種別=普通、事業用、燃料=軽油 など）も NULL になる。部分更新には使えない。
3. **必須項目の検証が弱い**: 運輸支局・分類番号・用途区別が空でも検証せず INSERT を試みる。これらのDB列は NOT NULL のため、新規 INSERT は DB エラー（エラー件数に計上、メッセージ「INSERT 失敗: …」）となる。上書き時は DB の設定により失敗または空文字更新になる。
4. マスタ（運輸支局・分類番号・用途区別）に存在しない値でもそのまま取り込まれる（マスタには自動追加されない）。その後、マスタ管理画面ではその値が一覧に出ず、車両一覧の運輸支局プルダウンには出る。
5. 取込は**トランザクション管理されていない**。途中でエラーが起きても、成功した行はすでに保存されている。やり直しは「スキップ」モードで再実行すれば重複登録はされない。
6. 乗車定員が空欄の場合、DB 既定値（2）ではなく **NULL** が保存される（フォーム登録と挙動が異なる）。
7. プレビューは重複の有無を判定しないため、「有効行合計」は実際の新規登録件数と一致しない場合がある。
8. 車台番号の列自体がCSVに無いと、全行スキップされ何も取り込まれない（エラー表示もなし）。
9. 取込後、タグ（`vm_tag_data`）が置換される。初期タグは DB の利用状況で上書きされる。
